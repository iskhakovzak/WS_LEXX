# Переименование человека (везде, вместе с данными)

Имя (`users.name`) — ключ всех данных человека: сделки (`trades.trader`), журнал, академия, уведомления, привязка
счёта PropReports, квесты, риск-лимиты и ещё около 150 колонок. Переименование меняет их **все в одной транзакции**
(`artifacts/api-server/src/lib/people/renameUser.ts`, список колонок — `renameUserColumns.ts`):

- **переименовывается:** имя в каждой колонке-ключе и колонке «кто сделал» (`created_by`, `reviewed_by` …), имена внутри
  JSON (параметры уведомлений, `shared_with` сетапов, рейтинги сезонов, снимки лимитов), ключи вида
  `risk:risk_breach:<имя>:<день>`, ссылки в уведомлениях (`/risk?trader=<имя>`), список пилотных пользователей
  (`usage.pilotUsers`), назначения куратора / ментора / риск-менеджера у других людей;
- **остаётся как было, нарочно:** журнал аудита (`audit_log` — неизменяемая история; само переименование пишется туда
  записью `user.rename` с `from` / `to` и числом перенесённых строк), свободный текст (комментарии, заметки,
  «@Имя» внутри уже написанных сообщений, готовые тексты старых уведомлений), логи ошибок и задач, рыночные данные;
- **отказ без изменений:** имя уже занято (сравнение как при входе: регистр, ё/е, пробелы; в том числе чужое латинское
  имя) или под новым именем уже лежат записи (остались от другого человека / импорта) — сначала разобраться с ними;
- все сессии человека завершаются (имя зашито в токен) — он входит заново под новым именем; браузер при входе сам
  переносит свои локальные настройки со старого имени.

Два способа — результат одинаковый:

1. **Админка → Люди → строка человека → «⋯» → «Переименовать…»** (после выкладки этой версии).
2. **Скрипт на сервере** `rename-user` — с пробным прогоном, который печатает, сколько строк в какой таблице поменяется.

## На сервере: Закир → Zakir Iskhakov

Владелец (`users.id = 1`). Всё ниже — на сервере, под своим пользователем с sudo.

### 1. Выложить версию с каскадным переименованием

Обычное обновление (раздел 8 [DEPLOY.md](DEPLOY.md)): дамп в `pre-update/`, `git pull`, сборка, рестарт, проверка
`/api/healthz`. Дамп обязателен — это точка отката.

### 2. Пробный прогон (ничего не пишет)

```bash
sudo -u wslexx -H bash -lc '
  set -a; . /etc/ws-lexx/api.env; set +a
  cd /opt/ws-lexx/app/artifacts/api-server
  pnpm run rename-user -- --id 1 --name "Zakir Iskhakov" --latin "Zakir Iskhakov" --dry-run
'
```

Проверьте вывод: первая строка `user 1: «Закир» → «Zakir Iskhakov», N rows in M columns`, дальше таблицы по убыванию
(первой должна быть `trades.trader` с числом сделок владельца). Если видите `refused: USER_NAME_TAKEN` или
`RENAME_DATA_CONFLICT {…}` — ничего не меняли; пришлите вывод, разберёмся.

### 3. Переименовать

Тот же вызов с `--confirm` вместо `--dry-run`:

```bash
sudo -u wslexx -H bash -lc '
  set -a; . /etc/ws-lexx/api.env; set +a
  cd /opt/ws-lexx/app/artifacts/api-server
  pnpm run rename-user -- --id 1 --name "Zakir Iskhakov" --latin "Zakir Iskhakov" --confirm
'
sudo systemctl restart ws-lexx-api      # кэши имён и настроек в памяти API перечитываются при старте
curl -fsS https://desk.example.com/api/healthz
```

`--latin` сразу задаёт и латинское имя (то, что видят читатели на английском и узбекском) — отдельно ничего делать не
нужно. Без скрипта: «Переименовать…» в админке (шаг 2 не нужен — админка сама откажет при конфликте), затем
латинское имя в «Админка → Люди → «⋯» → «Латинское имя…»» → `Zakir Iskhakov`.

### 4. Войти заново

Старая сессия закончится сама. На экране входа в поле «Ваше имя на деске» введите **Zakir Iskhakov** и свой пароль
(пароль не меняется).

### Проверка

- «Сделки» показывают все ваши сделки (число как в пробном прогоне у `trades.trader`);
- «Админка → Аудит»: запись «переименовал Закир → Zakir Iskhakov» с числом перенесённых записей;
- журнал, академия, уведомления на месте.

### Откат

Переименование обратимо тем же скриптом (`--id 1 --name "Закир" --latin "Zakir" --confirm`). Если что-то пошло
совсем не так — восстановить дамп из шага 1 (раздел 7 DEPLOY.md, «Восстановление рабочей базы»).

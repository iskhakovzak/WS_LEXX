# Область: «Торговля» (сделки, плейбук, правила, риск, масштабирование, что-если, калькулятор, идеи)

## Итог
Технически область в хорошем состоянии. Все ~300 вызовов API ответили быстрее 0,2 с. Чужие сделки, правила и лимиты закрыты для трейдера (403/404). Деньги считаются одной формулой (net = gross − |fees|), и итог по chert совпадает на всех экранах: $453,27 в «Сделках», в «Риске» и на главной. В EN/UZ-словарях нет русских строк, в коде нет захардкоженных имён и TODO. 205 юнит-тестов области зелёные. При этом тесты не ловят ни одну из главных проблем ниже.

Сильнее всего болит то, что защита денег сделок есть только в интерфейсе. Через API трейдер может переписать pnl своей брокерской сделки (проверено: 200), удалить её (синхронизация её больше не вернёт), завести ручную сделку и удалить исполнения. Второе по силе: замки уровней в плейбуке «текут» через соседние эндпоинты. Третье: одна и та же разметка живёт в 2–3 местах, поэтому цикл «сделка → разбор → плейбук» не замыкается. Трейдер ставит сетап на /trades или в дневнике, а счётчик «Без сетапа» и квест не меняются.

**Первыми я бы сделал:**
1. Серверный запрет для не-персонала менять, удалять и создавать денежные поля брокерских сделок и их исполнений.
2. Тег сетапа везде (S на /trades, вечерний дневник) пишет `playbook_id` одного из 16 сетапов офиса.
3. Одна проверка замка уровня на всех `/playbook/:id/*` и в `for-trade`. Плюс новое правило не должно заливать куратору нарушения за полгода.

## Разделы

### Сделки (/trades) — разбор своей торговли по дням: разметка, разбор, переход в плейбук, дневник и реплей
- **Проверено:** `GET /trades/page`, `/trades/days`, `/trades/:id`, `/trades/:id/{quality,executions,ai-review}`, `/trade-executions/batch`, `/trades/quality`, `/voice-notes`, `/ai-review/usage`, `/playbook-tools/for-trade/:id` под всеми тремя ролями. Чужие id, несуществующий id (404), `abc` (400). `PATCH /trades/:id` от трейдера. `POST /trades/bulk` на чужую сделку (forbidden:1). Языки через `X-Lang`.
- **Работает:**
  - Сводка, дни и пагинация отвечают за 5–15 мс. Скоуп трейдера жёсткий: `?trader=Закир` молча отдаёт свою книгу, `?ids=` с чужими id — пусто.
  - Net, PF и win rate совпадают с «Риском» ($453,27; PF $ 1,15).
  - Мягкое удаление с «Отменить» работает. Переход «Разбор дня» есть.
- **Ошибки:**
  - **[P0] Деньги своих сделок меняются через API в обход интерфейса.** Интерфейс прячет правку и удаление брокерских сделок только на клиенте (`pages/trades.tsx:99` `canEditForm`). Сервер проверяет одно: «сделка своя».
    - `PATCH /trades/:id` с `pnl/fees/qty/exit/result` от трейдера → 200 (проверено на 236675 с теми же значениями). Защита чек-листом касается только ticker/date/side/entry/stop/setup/eventType (`routes/trades.ts:622` и далее).
    - `DELETE /trades/:id` и `POST /trades/bulk {action:"delete"}` по своей брокерской сделке разрешены. Синхронизация PropReports удалённые сделки пропускает навсегда (`lib/propreports/sync.ts:335` `skip: deleted`). Трейдер может «стереть» убыток из статистики, рейтингов и квестов.
    - `POST /trades` с `skipChecklist:true` создаёт ручную сделку с любым pnl (`routes/trades.ts:529`), хотя по модели данных сделки приходят только из PropReports.
    - «Риск» и «Масштабирование» берут брокерские строки, если они есть (`lib/riskData.ts:88`, `lib/scalingEngine.ts:321`), а «Сделки» и рейтинги — все строки. После такой правки цифры разойдутся.
  - **[P1] Исполнения брокерских сделок трейдер видит с корзиной и формой «Добавить».** Удаление одним кликом, без подтверждения и отмены, жёсткий `DELETE` (`components/trades/ExecutionsPanel.tsx:215`, `routes/executions.ts:263`). Ломает реплей, качество входа и «роли» исполнений. В интерфейс передаётся `canEdit`, а не `canEditForm` (`TradeDetailSheet.tsx`, вкладка «Исполнения»).
  - **[P1] Тег сетапа на /trades (клавиша S) пишет свободный текст `trades.setup`, а не `playbook_id`** (`components/trades/review-tagging.tsx:34`).
    - Варианты в списке — старые тексты сетапов трейдера. У нового трейдера список пуст, 16 сетапов офиса там нет.
    - Счётчик «Разметить N сделок», квест «разметить вчерашние» и edge/разблокировка сетапа считают только `playbook_id` (`lib/playbookToday/untagged.ts`).
    - То же в вечернем дневнике (`components/eod/eod-api.ts:127`).
    - `POST /playbook/auto-link` и `GET /playbook/unlinked-suggestions` никто в вебе не вызывает.
    - Проверено: после PATCH `setup` поле `playbook_id` осталось NULL (изменение откатил).
  - **[P2] Подсказка у плашки дня не соответствует расчёту.** Текст: «Закрытые сделки без сетапа, тегов и заметок» (`i18n/locales/ru/trades.ts:182`). SQL `untaggedSql` сетап и теги не учитывает, только оценку и текст разбора (`lib/tradesPageQuery.ts:155–163`).
  - **[P2]** `PATCH /trades/:id` не проверяет `deleted_at`: удалённую сделку можно править (`routes/trades.ts`, выборка `existing`).
  - **[P2] Голосовые заметки зависят от Replit Object Storage** (`routes/voicenotes.ts:90`). Бакет `DEFAULT_OBJECT_STORAGE_BUCKET_ID` нужен и для бэкапов, а их, по прошлому аудиту, нет. Без бакета загрузка падает с 500 `STORAGE_FAILED`. В базе 0 заметок за всё время. Ещё `POST /voice-notes` не проверяет, что `tradeId` — своя сделка.
- **UX (по законам владельца):**
  - Карточка сделки: 6 вкладок. «График» и «Реплей» — один и тот же движок. Блок «Качество» повторяется в «Обзоре» и «Реплее». В «Обзоре» 9 секций подряд, фокус размыт.
  - Слова: «Без разбора» = нет оценки/текста, «Без сетапа» = нет `playbook_id`. Для chert это 270 и 3 соответственно, а разметка S не уменьшает ни то, ни другое.
- **Улучшения:**
  - Выпадающий список S = незакрытые сетапы офиса (код + название) с записью `playbook_id`. Зачем: один тег закрывает «Без сетапа», квест и копит edge сетапа. Усилие S, эффект на цикл H.
  - Карточка: «Обзор» = разметка + разбор + график; «Исполнения» и «AI» свернуть. Усилие M, эффект M.

### Плейбук (/playbook) — утром выбрать сетапы дня («Сегодня»), вечером пополнять эталоны; кураторы ведут офисную книгу
- **Проверено:** `GET /playbook`, `/playbook/today`, `/me`, `/summary`, `/health`, `/tags`, `/folders`, `/folder-settings`, `/playbook-tools/{inbox,gallery,trade-picker,for-trade,share-targets}`, `/playbook/203/{examples,stats,edge,children,trades,checklist-runs,revisions,marks,activity,ideas,reviews}`. Все от трейдера-«стажёра» (chert без ступени = стажёр, 11 из 16 сетапов под замком). `POST /playbook/203/examples` на закрытый сетап, затем удаление. EN-ответ «Сегодня».
- **Работает:**
  - Список `/playbook` отдаёт закрытые сетапы без содержимого (`locked:true`, поля пустые).
  - «Сегодня» показывает окна дня и условие открытия («10 сделок с оценкой A по 1.3»). Выбор сетапов дня пишется в план дня (одна сущность с «Планом»). `PUT /today/picks` проверяет замок.
  - Режим по умолчанию у трейдера — «Сегодня», один фокус.
- **Ошибки:**
  - **[P1] Замки уровней обходятся.** Замок проверяется только в `GET /playbook`, `/children`, `/revisions` и при выборе сетапов дня (`routes/playbook.ts:310, 1028, 1133`). Нет проверки в `setupForRead` (`routes/playbook-spaces.ts:123`) и в `for-trade` (`:470`). Проверено:
    - `GET /playbook-tools/for-trade/236675` от стажёра отдаёт `checklistItems` и текст `checklist` всех 16 сетапов, включая 11 закрытых (критерии «A-сделки» Gap & Go, VWAP Fade, MOC…).
    - `POST /playbook/203/examples` (1.1 Gap & Go, уровень junior) от стажёра → 201. Пример удалён.
    - Без проверки замка также `GET /playbook/:id/examples`, `PUT /playbook/:id/marks/:itemId`, `POST /playbook/:id/checklist-run` (у последнего нет даже проверки, что сетап виден).
    - Прошлый аудит пишет «замки работают на сервере» — это верно только для списка.
  - **[P2]** Условие открытия «10 сделок с оценкой A» считает оценки, которые трейдер ставит себе сам в дневнике (`lib/playbookToday/service.ts:73`). Куратор их не подтверждает.
- **UX:**
  - Режим «Сегодня» сделан хорошо.
  - Библиотека для персонала: 3 режима × 3 вида × 4 пространства × 6 фильтров × 5 сортировок + сравнение, экспорт в Markdown и Notion, масштаб, горячие клавиши. Закон «меньше выбора» нарушен, но это экран кураторов.
  - У всех 16 офисных сетапов 0 эталонов. Карточки «Сегодня» обещают «реальные графики-примеры», а показывают пусто.
  - Содержимое сетапов только на русском, в том числе для EN/UZ (ответ `?X-Lang=en` содержит русский текст). Это контент, не код.
- **Улучшения:**
  - Одна функция `assertSetupReadable(req, id, {unlocked:true})` во всех `/playbook/:id/*` и фильтр закрытых в `for-trade`. Усилие S, эффект M: замки начнут значить то, что обещано.
  - Кураторам наполнить 2–3 эталона Tier 1 на каждый из 16 сетапов. Усилие M (контент), эффект H: утренний экран станет обучающим.
- **Вопросы владельцу:**
  - Разблокировка сетапов по самооценке «A» — нормально, или нужен куратор («A» подтверждает куратор)?
  - Переводить ли 16 шпаргалок на UZ для стажёров?

### Правила и ошибки (/rules, /error-tracker — тот же экран) — личные и офисные правила, авто-нарушения, журнал ошибок
- **Проверено:** `/rules`, `/rules/kinds`, `/rules/report`, `/rules/preview`, `/rule-violations` (+count, +archived), `/errors`, `/errors/summary`, `/rules/discipline`, `/rules/self-checks` от трёх ролей, в том числе по чужому трейдеру (трейдер → 403). Создал правило «≤ 3 сделок/день» от трейдера, посмотрел нарушения, удалил правило. Перевод нарушений на EN.
- **Работает:**
  - Права корректны. Предпросмотр правила полезен: «24 нарушения за 90 дней, −$120,84 на нарушениях против +$269 на чистых сделках».
  - Удаление правила архивирует нарушения. Тексты нарушений переводятся по ключу.
- **Ошибки:**
  - **[P1] Новое правило заливает очередь нарушениями за всю историю.** Создание правила запускает `scanRulesForTrader` без окна по датам (`lib/rulesEngine.ts:356–360`, `fetchTrades(trader)` без `range`). Правило, созданное сегодня, сразу дало 60 открытых нарушений с 04.05 по 24.09. У всех `occurredAt` = сейчас. Это ровно тот «шум», из-за которого в прошлом аудите архивировали 1 043 нарушения.
  - **[P1] На деске нет ни одного правила и нет наборов правил по уровням.** `trading_rules` пуст, общих правил `'*'` нет. Правила не зависят от уровня (Стажёр/Джун/…). У chert нет даже лимитов риска. Новый трейдер начинает без правил и без стопа, значит, у куратора в цикле нечего разбирать. Шаблоны лимитов по тирам есть (`/risk/templates`), но автоматически не применяются.
  - **[P1] Ошибки живут в трёх местах.** Клавиша M на /trades → `trades.tags`. Вечерний дневник → `eod_trade_reviews.mistakes`. «Правила → Ошибки» → `trading_errors`. Словарь общий, хранилища разные. «Убыточные сделки без ошибки» в `/errors/summary` (`routes/errors.ts:261`) не видят ни тегов, ни ошибок из дневника.
  - **[P2]** Отчёт без единого правила отдаёт «48 чистых дней подряд» и недельную дисциплину 100 % (`/rules/report`, `totals.currentStreak/weekly.compliance`). Сейчас интерфейс показывает вместо этого онбординг, но любой новый потребитель покажет ложные 100 %.
  - **[P2]** Трейдер может удалить своё личное правило, и все его нарушения уйдут в архив, в том числе неразобранные куратором.
- **UX:** вкладки «Ошибки» и «Нарушения» трудно различить по смыслу (ручные и авто). Плюс отдельный «Что если» с тем же вопросом «что было бы, если бы я соблюдал правило».
- **Улучшения:**
  - При создании правила сканировать только с даты создания, историю показывать в предпросмотре. Усилие S, эффект H для куратора.
  - Набор правил деска по уровням (Стажёр: ≤ N сделок/день, пауза после 2 убытков, дневной стоп) и автоприменение шаблона лимитов при назначении ступени. Усилие M, эффект H: у каждого новичка с первого дня есть что соблюдать и что разбирать.
  - Одно хранилище ошибок: M на /trades и дневник пишут в одну таблицу. Усилие M, эффект M.

### Риск (/risk) — дневной, недельный стоп и просадка трейдера; деск куратора; овернайт
- **Проверено:** `/risk/me`, `/desk`, `/history`, `/positions`, `/overnight`, `/alerts`, `/breaches`, `/limits/:t`, `/limits/:t/history`, `/templates`, `/summary`, `/check` × 3 роли × 2 трейдера; RU/EN/UZ.
- **Работает:**
  - Трейдер видит только себя, деск и шаблоны — 403. Тексты стопов в EN/UZ переведены.
  - Капитал и просадка совпадают с «Сделками» (equityNet 453,27).
  - Правка лимитов закрыта правом `risk.limits.edit`.
- **Ошибки:**
  - **[P2] Одна и та же длящаяся просадка считается повтором каждый день.** Пример — Закир: алерты 16911 и 16912. `/risk/summary.repeatBreachers` показывает «2 дня из 7», а это одно событие. «Масштабирование» считает такую просадку правильно — один раз на окно (`lib/scalingEngine.ts:397`).
  - **[P2]** Владелец-админ на стопе («торговля остановлена», 118 % лимита просадки). Его нет в таблице деска (там только роль trader, `/risk/desk` traders=1), но он есть в `/risk/summary.breachesToday`. На одном экране «остановленных 0», на соседнем — нарушение.
  - **[P2]** Разбор нарушения не запрещён самому нарушителю, если он персонал. Куратор или админ, который торгует, может сам разобрать свою просадку и тем самым сбросить отсчёт (`routes/risk.ts:848`, `actor === trader` разрешено).
  - **[P2]** `GET /risk/check` (проверка позиции до входа) нигде в вебе не используется: мёртвый эндпоинт.
- **UX:** стажёр видит вкладку «Овернайт», хотя овернайт ему запрещён. В простом меню стажёра /risk нет, так что для него это не проблема.
- **Вопросы владельцу:** решение 7 из прошлого аудита (окно просадки, блокирует ли стоп) всё ещё открыто. Админ сейчас «на стопе».

## Сквозные находки по области
- **Безопасность:** кроме P0 по деньгам сделок, права проверены и работают. Чужие сделки, правила, лимиты и разборы дают 403/404. Сырого SQL с подстановкой нет: `DESK_TRADER` — константа. Загрузки голоса ограничены 25 МБ и mime-фильтром.
- **Производительность:**
  - Всё быстрее 0,2 с, кроме цепочки опционов (0,94 с, внешний источник).
  - `GET /trades` без окна для админа отдаёт 1,55 МБ (весь деск). На 45 тысячах сделок будет десятки МБ.
  - Вызывается из легаси-веток `fetchAllTradesLegacy` (`hooks/use-trades-page.ts:221`) и `DataSection` — на случай «старого API», которого больше нет.
  - `trade-picker` отдаёт 107 КБ (обрезано до 300 сделок, нормально).
- **i18n:** EN/UZ-словари области без русских строк, ключи сверяет tsc. Русские литералы в коде только как данные и раскладка клавиатуры. Не переведены контентные данные: 16 сетапов плейбука, названия и описания тиров в базе (клиент переводит дефолтные).
- **Заметка для лида:** язык API выбирается заголовком `X-Lang`, а не `Accept-Language` (`i18n/index.ts:125`). С `Accept-Language: en` API отвечает по-русски.
- **Телефон (по коду):** /trades и карточка сделки адаптивны (исправлено в прошлом аудите). «Сегодня» плейбука в одну колонку. Таблицы риска и масштабирования в `DataTable` со скроллом — это экраны кураторов. Явно десктопных экранов для трейдера не нашёл.
- **Мёртвый код:**
  - `pre-trade-checklist.tsx`, `POST/GET /checklist-responses`
  - `GET /risk/check`
  - `POST /playbook/auto-link`, `GET /playbook/unlinked-suggestions`
  - `fetchAllTradesLegacy`
  - `POST /trade-ideas/:id/convert` (отвечает «retired»)
  - Голосовые заметки (0 записей) и AI-разборы (0 записей) — живые, но не используются.
- **Тесты:** 9 файлов, 205 тестов области зелёные. Ни один не проверяет запрет денежных полей брокерской сделки, замок в `for-trade`/`examples` или окно сканирования правил.
